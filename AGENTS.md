# AGENTS.md

## Project Overview

**bing-wallpaper** — Archives Bing's daily wallpapers (Chinese + international) and publishes them as a static site on GitHub Pages.

- **Runtime**: Bun (1.4+) — `bun test`, `bun check`, `bun fmt` are built-in, no extra config files
- **Language**: TypeScript (ESM, `strict`, `noUncheckedIndexedAccess`, imports use explicit `.ts`/`.tsx` extensions)
- **Rendering**: Hono + `hono/jsx`, pre-rendered to static HTML with `hono/ssg` (`toSSG`)
- **Data**: `data/wallpapers.json` is the only persisted state; images are hot-linked from Bing (not downloaded)
- **Deploy**: `.github/workflows/deploy.yml` → GitHub Pages

## Scripts

| Script               | Description                                                 |
| -------------------- | ----------------------------------------------------------- |
| `bun run dev`        | `build` then `serve` — local preview of `dist/`             |
| `bun run build`      | Render the site into `dist/` (offline, uses committed JSON) |
| `bun run serve`      | Serve existing `dist/` on Bun.serve (run `build` first)     |
| `bun run wallpapers` | Fetch both Bing endpoints and append new items to the JSON  |
| `bun run backfill`   | Fill recent gaps from a public archive (best-effort)        |
| `bun run markdown`   | Regenerate `README.md` from the JSON                        |
| `bun test`           | Run tests (`src/*.test.ts`, `bun:test`)                     |
| `bun check`          | Type-check via `tsconfig.json`                              |
| `bun fmt`            | Format code (`bun fmt --check` to verify without writing)   |

```
├── src/
│   ├── wallpapers.ts      # Types + pure helpers: parse/validate/dedupe/sort/thumbnail
│   ├── data.ts            # Imports data/wallpapers.json as Wallpaper[]
│   ├── index.tsx          # Hono app: <App>, <Gallery>, <Home>; exports `app`
│   ├── Wallpaper.tsx      # Single card component (400px thumbnail)
│   ├── styles.css         # Copied to dist/styles.css at build time
│   ├── build.ts           # toSSG(app) → dist/, then copies styles.css
│   ├── index.test.ts      # Homepage render tests
│   └── wallpapers.test.ts # Unit tests for the helpers
├── scripts/
│   ├── wallpapers.ts      # Fetch cn + www, dedupe, write JSON (CLI)
│   ├── backfill.ts        # Fill missing recent dates from a public archive (CLI)
│   ├── markdown.ts        # Write README.md (CLI)
│   └── serve.ts           # Static file server for dist/
├── data/wallpapers.json  # Generated archive (do not hand-edit)
├── dist/                 # Generated site (git-ignored)
├── README.md             # Generated by `bun run markdown` (do not hand-edit)
└── .github/workflows/deploy.yml
```

## Data Flow

```
data/wallpapers.json
   ├─→ src/data.ts → wallpapers.ts (normalize) → index.tsx → build.ts → dist/
   ├─→ scripts/markdown.ts → README.md
   ├─← scripts/wallpapers.ts (append new ids, clean, write back)
   └─← scripts/backfill.ts (fill missing dates from a public archive)
```

## Conventions

- **Wallpaper shape**: `{ enddate: "YYYYMMDD", copyright, url }`. `url` stores only `https://<host>/th?id=...` with **no size params**; thumbnails are produced at render time by `thumbnailUrl(url, width)`.
- **JSON ordering**: written sorted by date **ascending** and deduplicated by image id (`clean()`) so git diffs stay minimal; display order is **descending** (`normalize()`).
- **Homepage size**: only the latest `RECENT_LIMIT` (365) entries are rendered, split into `cn` / `www` groups by `sourceOf()`.
- **Two sources**: `https://cn.bing.com` (`mkt=zh-CN`) and `https://www.bing.com`. Any change to fetching logic must be checked against both; a single source failing must never wipe existing data (see `allFailedOrEmpty` guard + non-zero exit codes).
- **Backfill safety net**: Bing's API only serves the last 8 days, so `bun run backfill` fills missing dates within the last 90 days from a public daily archive (zh-CN + en-US). It does no network work when there are no gaps, and archive failures only log a warning — never fail the job. Set `ARCHIVE_DIR` to use local archive snapshots.
- **No mutation**: CLI scripts must not mutate the imported `wallpapers` array in place (copy before sorting).
- **Generated files**: never edit `data/wallpapers.json` or `README.md` by hand — run `bun run wallpapers` / `bun run backfill` / `bun run markdown`.
- **Comments in English**, explaining _why_ (the code is already self-documenting).
- Keep helpers in `src/wallpapers.ts` pure and covered by `src/wallpapers.test.ts`; add a unit test whenever you touch sorting, dedupe, URL parsing, or limits.

## CI (`.github/workflows/deploy.yml`)

- Every push/PR: `bun check` + `bun test` + `bun run build`.
- Push to `main`, the daily 17:00 UTC cron, and manual `workflow_dispatch` additionally run `bun run wallpapers` + `bun run backfill` + `bun run markdown`, then commit **only** `data/wallpapers.json` and `README.md`, and deploy `dist/` to Pages.
- Gate the collection step on `github.event_name != 'pull_request'`. Never use `== 'push'`: cron runs report `event_name == 'schedule'`, which once made the daily job succeed while silently skipping collection.
